# 批次4交付：0.1g 精准组方引擎（核心算法层）

交付4个文件：`tcm_kb.sqlite`（新增9张表的成品库）、`build_batch4_tables.py`
（数据层重建脚本）、`dosage_engine.py`（引擎+自测）、本说明。

上游对接：直接吃批次3 `SyndromeWeightEngine.evaluate()` 的返回值，
加上患者画像/批1指标/批2舌象，输出逐味克数 + 全链路审计。

---

## 一、这个引擎为什么敢上生产：五条设计立场

1. **剂量不经过大模型。** 全流程是确定性加权乘法+硬钳位，同输入永远同输出，
   可复算、可审计、可追责。LLM 只在模块6把 audit 翻译成人话，不参与算数。
2. **基础方加减，不自由组方。** 主证型选经典方（有《伤寒论》《方剂学》出处），
   兼证≥15%按加味表加药。自由组药无法举证。
3. **药典是天花板不是参考值。** 任何系数算出的结果都被 `herb_pharm.dose_max_g`
   硬钳，系数只能在药典区间内浮动，**永不突破**。
4. **不确定就不出方。** 命中闸门即 BLOCK 并返回原因，而不是降级出一个方。
5. **默认待执业中医师签发**，输出标的是"处方建议"不是可直接抓药的处方。

## 二、数据层：新增9张表（在批次3的库上原地扩建）

| 表 | 量 | 血统 | 用途 |
|---|---|---|---|
| **herb_pharm** | 565味，**502味有药典剂量区间** | 492味[KB]自动抽取 / 10味[TEXT]人工补录 | **硬钳位依据** + 四气五味归经 + 毒性 |
| herb_alias | 炮制名归一 | [KB] | 炙甘草→甘草、法半夏→半夏 |
| herb_ratio | 842味 | [KB]药典成方配比 | 君臣佐使比例参考 |
| herb_classic_dose | 400味 | [KB]古方+dose_convert(汉方已÷3服) | 古方剂量参考（不作钳位） |
| safety_incompat | 60条 | [TEXT]十八反十九畏 | 配伍禁忌硬拦 |
| safety_flag | 115条 | [TEXT]+[GOV]+[KB] | 妊娠/肝毒/肾毒/儿童/马兜铃酸禁用 |
| food_herb | 108味 | [GOV]药食同源目录 | 前端"食药同源"标识 |
| base_formula(_herb) | 18首/130条 | [TEXT]方剂学教材 | 基础方+君臣佐使+基准量 |
| syndrome_formula_map / addon | 17+16条 | [TEXT] | 证型→方、兼证→加味 |

**血统标记是强制的**：`[KB]`=从库里自动抽取可复现，`[TEXT]`=教材/药典附录须药师复核，
`[GOV]`=官方目录须核对最新公告。三类在 `src` 字段里写死，审计时一眼分得清。

体检结果：基础方54味药 + 加味表16味药，**药典剂量覆盖率100%**（无钳位=安全漏洞，
故对KB样本未覆盖的10味常用药人工补录，单独标血统待药师逐条核对）。

## 三、剂量怎么算出来的（以画像A实测为例）

```
柴胡  9.0g × 1.06 × 1.0 × 0.898 × 0.85 = 7.28g → 钳[3.0,10.0] → 7.3g
      基准   证型   指标   体重    肝肾折减
```

- **K_证型**：主证占比20%→0.80，60%以上→1.20 线性；再按角色调幅
  （君1.0/臣0.7/佐0.5/使0.2），所以君药随证型强度大幅变化，甘草这类使药几乎不动。
- **K_指标**：批1的指标等级经 `LAB_RULES`（8条，独立成表可校准）换算，
  如甘油三酯↑G2 → 痰湿证相关药 +20%。
- **K_体重**：`(体重/60)^0.75` 按体表面积近似，钳在0.7~1.3；≥65岁再×0.85。
- **K_肝肾**：每级×0.85，G3直接BLOCK。
- **0.1g取整**：贴近上限时向下取整，保证永不越过药典天花板。

## 四、安全闸门（实测拦截率43.9%）

**硬拦不出方**：肝肾3级 / 辨证证据不足 / 寒热并重 / <12岁 / 马兜铃酸禁用品种 /
十八反 / 大毒药 / 妊娠+血瘀 / 妊娠+君臣药属妊娠慎用 / **基础方原方药材被剔除**。

最后一条是本批最关键的一次修正。原实现把禁忌药静默剔除后照常出方，
实测发现**孕妇阳虚证会拿到"去掉附子肉桂的金匮肾气丸"——即六味地黄丸，
温阳方退化成滋阴方，对证完全反了，而且不再是有出处的经方**。
现改为：原方任意一味被剔除即 BLOCK 转人工，只有兼证加味药允许安全去除。

另一次修正：**药典下限曾把安全减量顶回去**（72岁肾功G2患者，山药算出7.9g
被下限抬到15.0g、附子1.9g被抬到3.0g，减量方向完全反转）。
现改为上限硬钳、下限只提示不抬升，并上报"低于药典常用量下限，疗效可能不足"。

## 五、验收结果

- **2000次随机画像**（覆盖8证型×6年龄×5体重×肝肾0-3级×12%妊娠×过敏史）：
  出方1123 / 拦截877，**安全不变量违规 0 条**——无越药典上限、无非0.1g整数、
  无总量超200g、无大毒药入方。
- **确定性复算**：同输入两次输出完全一致 ✅
- **妊娠专项**：8证型中5个拦截、3个出安全方（逍遥散/四君子汤/八珍汤），
  出方中妊娠禁忌慎用药残留 **0 例** ✅

## 六、诚实缺口（必须在临床校准阶段解决）

1. **系数曲线是v1启发式**。`_k_syndrome` 的0.8~1.2、角色调幅、指标±8~10%，
   都是工程上合理但**没有临床验证**的取值。这些数字全部集中在
   `LAB_RULES` / `ROLE_AMP` / `_k_*` 三处，中医师可逐个校准而不动主流程代码。
2. **基础方只有18首**，覆盖八证型主要场景；真实临床需要扩到60~100首，
   且需按主诉科别细分（妇科/儿科/皮科的常用方完全不同）。
3. **人工补录的10味药剂量**必须由药师对着《中国药典》一部逐条核对签字。
4. **十八反十九畏、妊娠禁忌、药食同源目录**是按通行内容录入的种子数据，
   `need_review=1`，上线前须药师核对（药食同源目录尤其要核对卫健委最新公告，
   近年有多次增补）。
5. **毒理定量数据（LD50、蓄积毒性、安全剂量上下限）依然没有**。
   本批用"药典有毒标注→上限×0.7封顶"作为替代方案，这是定性不是定量。
   真要做剂量-毒性曲线，仍需药典+文献人工建库，下载不来。
6. 引擎不识别**中西药相互作用**（如华法林×丹参、他汀×红曲）。
   `patient.current_drugs` 字段已预留但规则表是空的，这是第5批的活。
