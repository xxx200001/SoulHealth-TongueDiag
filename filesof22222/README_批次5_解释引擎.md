## 一、对照规格书逐条交卷

规格书模块6要求"每组方必须自动生成4套强制解释，缺一不可"：

**维度1 宏观中医辨证** —— 病机/治法/调理思路来自新建 `syndrome_pathology` 表
（八证型，教材内容标 [TEXT] 待复核）；君臣佐使逻辑 + 每味功效来自
`herb_function`（564味，从药典QA自动抽取，[KB]可复现）；辨证证据清单直接
渲染批3的逐条 audit（证据→贡献分→教材依据）。

**维度2 微观临床医学（指标级）** —— 这是本批最需要立场的地方。规格书要求
解释"修复肝细胞、改善胰岛素抵抗"等机制，但库里**没有**成分-靶点-通路数据，
让 LLM 现编就是幻觉工厂。落地方案：新建 `herb_mechanism` 表（40条种子），
每条 = 药材×指标类别×方向×陈述×**证据级别**（临床研究/药理研究/传统经验），
措辞纪律只写"研究提示/显示"；引擎按用户异常指标**查表**，方中有对应药材才
输出；查不到就输出诚实空态（画像A的血清铁蛋白就是实例）。规格书里
"无肝肾损伤证明"式的绝对表述，本引擎在架构上就发不出来。

**维度3 精准克重逐条依据** —— 把批4每味药的 trace 翻成人话：基准量出处→
证型强度(角色调幅)→指标修正→体型年龄→肝肾折减→药典钳位(附原文与血统)→
0.1g取整。"多了会怎样"查 `herb_dose_risk`（16条真实超量风险：甘草假性
醛固酮、附子乌头碱、苦杏仁氢氰酸等），查不到则回落到"越出药典区间无安全性
依据"；"少了会怎样"用药典下限举证，君药加一句"动摇全方"，被安全折减压到
下限以下的药（BELOW_PHARM_MIN 标记）如实说明"安全优先于药效"的取舍。

**维度4 反向排除（铁律5）** —— 全部从引擎真实状态推导，不是套话：
为什么不加药 = 列出每个未达15%阈值的弱兼证及其实际占比 + 被安全剔除的加味
候选；为什么不加量 = 列出被药典上限封顶的药（附计算值）+ 肝肾折减系数 +
总量钳位；寒热核查 = `syndrome_pathology.avoid` 教材忌用方向 + **全方四气
实测分布**逐味统计——阳虚方里出现泽泻/牡丹皮（寒凉）时，引擎能正确识别其
为经方原配的佐制药并举证"阴中求阳"，而不是装没看见或误报；为什么此方最优 =
选方触发条件 + 列出同证型未选中的备选方及其适用条件。

**拦截也是解释**：11个拦截码全部配了三段式文案（系统判定/为什么这在保护你/
下一步建议），"不出方"从一个错误码变成一次负责任的沟通。

## 二、LLM 的位置：润色可选，幻觉出不了门

架构是 `模板输出（默认即完整可用）→ build_llm_prompt(全部事实JSON+铁律)
→ LLM → verify_polished 三重校验 → 不过即回落模板并留痕`。三重校验：
①数字子集——润色稿的每个数字必须在事实JSON里出现过（禁止改克数/换算/编数）；
②药名白名单——用全库2300+药名词典扫描，出现任何不在本方事实内的药名即拒；
③禁语——根治/治愈/无副作用/绝对安全等承诺性措辞即拒。
自测里故意投喂的幻觉稿（"加冬虫夏草30g，根治，绝对安全"）被以
"新增药名+禁语"两个理由拒绝并回落。**这意味着接任何 LLM（扁仓14B或商用API）
都不需要信任它——信任在校验器里。**

## 四、诚实缺口

1. **herb_mechanism 只有40条种子**，覆盖18首基础方常用药×8类指标的主干场景。
   每条 need_review=1，上线展示前必须逐条补文献编号（PMID/DOI）并经医师复核
   ——这是数据工程活，引擎侧已留好 src/evidence_level 字段。
2. **维度2覆盖不到的指标一律诚实空态**。规格书期望的"调节肠道菌群、清除
   自由基"这类泛机制，现库无证据支撑，本引擎不会说。要扩就扩表，别松架构。
3. syndrome_pathology / herb_dose_risk 是教材通行内容的种子录入，须中医师
   /药师复核（need_review=1）。
4. 批3的 audit 若未传入，维度1证据清单会缺失并明确提示——联调时注意把
   evaluate() 的完整返回透传过来。
5. LLM 数字校验是"子集"逻辑，理论上润色稿可以**漏说**数字（不能新增）；
   如需强制关键数字必现（如每味克数），可在 verify 里加必现清单，一行配置的事。
